# Core engine (plan 1): decisions made during the build

Decisions the build controller made on Kaan's behalf while executing plan 1, each with what it costs if wrong. Rework any you disagree with.

- Ruling R1: repo initialized and docs committed on main by controller; T1 skips `git init` and extends existing .gitignore — keeps docs history separate from code — cost if wrong: none.
- Ruling R2: ProtectedPaths resolves allowedRoots, home and hard-deny entries with the same realpath/parent-resolution as the candidate before comparing — otherwise /var vs /private/var (temp dirs) breaks containment — cost if wrong: a containment bug, caught by T2 tests.
- Ruling R3: largeOldDownloads filter uses logical file size (fileSizeKey) for the ≥500 MB threshold; reported bytes stay allocated size — makes the sparse-file test meaningful and matches what users see in Finder — cost if wrong: small mismatch for sparse files only.
- Ruling R4: CleanupRunner sets restorable = (any entry is movedToTrash); emptyTrash runs are restorable = false — cost if wrong: History marker wrong, low.
- Ruling R5: CleanupRunner.run gains `extraEntries: [JournalEntry] = []`, appended after its own entries before save/log; Uninstaller passes bootout failures and needs-admin leftovers through it (app bundle stays first) — keeps one journal/log write per run — cost if wrong: small API change in T7.
- Ruling R6: keep T12's reuse of DeletionOutcome for toggle results as the plan states — cost if wrong: a later rename to a dedicated enum.
- Ruling R7: `public init(environment: SystemEnvironment, commands: CommandRunning)` for HealthCheck — cost if wrong: trivial.
- Ruling R8: for DIRECTORIES in Downloads the 500 MB threshold uses DirectorySizer allocated bytes (no logical-total API); files use logical size per R3 — sparse directories are rare — cost if wrong: a sparse dir under-qualifies.
- Ruling R9: RestoreOutcome gains `failed(String, reason: String)` for per-entry move errors — otherwise a move error would abort or be swallowed — cost if wrong: one extra enum case
- Ruling R10: RunJournal.all() returns decodable runs and `unreadableRecords()` lists files that failed to decode — a corrupt file must neither crash History nor vanish silently — cost if wrong: small API change
- Ruling R11: restore saves after each successful move; on a save failure it stops moving further entries and throws RunJournalError.saveFailed(outcomes:, underlying:) carrying outcomes so far — keeps the journal consistent with disk and keeps the throws -> [RestoreOutcome] signature — cost if wrong: extra writes per entry
- Ruling R12: AppScout adds `discoverWithIssues() -> (apps, unreadable: [URL])`; `discover()` returns `.apps` — keeps plan signature while surfacing unreadable app folders — cost if wrong: one extra method
- Ruling R13: LeftoverFinder rejects untrusted path components (empty, ".", "..", containing "/", ":" or NUL) from bundle IDs, team IDs, names and Steam installdir; every leftover's parent must be a declared location dir — prevents path traversal into user folders that aren't hard-denied — cost if wrong: odd-named apps lose leftover detection
- Ruling R14: launch agent Label / PrivilegedHelperTools prefix matches require a dot boundary (== B or hasPrefix(B + ".")) — prevents com.foo matching com.foobar — cost if wrong: missed leftovers for helpers named without a dot
- Ruling R15: B.-prefix matching (ByHost, Label, helpers) only when B has ≥3 non-empty dot components; otherwise equality only. Team IDs must match ^[A-Z0-9]{10}$ — stops generic IDs from claiming system-wide items — cost if wrong: misses leftovers of apps with 2-component IDs (equality still works)
- Ruling R16: ByHost match requires name == B + "." + <segment without dots> + ".plist" — real ByHost host parts are UUID/MAC — cost if wrong: misses odd ByHost names
- Ruling R17: new `leftovers(for:among installed: [InstalledApp] = [])`; a Label/helper/ByHost match that also matches a longer installed bundle ID (equal or dot-prefix) is skipped; a Group Container whose team ID is shared by another installed app gets match .nameBased — prevents claiming sibling apps' data — cost if wrong: API grows by one optional parameter
- Ruling R18: new `leftoversWithIssues(for:among:) -> (leftovers, issues: [ScanIssue])`; `leftovers(for:among:)` returns .leftovers. ScanIssue gains `case commandFailed(command: String, reason: String)`; unreadable location dirs → .missingFullDiskAccess (EPERM/EACCES) or .unreadable; SizeResult.unreadable → .unreadable; pkgutil launch failure → .commandFailed — honors never-fail-silently without breaking the plan signature — cost if wrong: extra API
- Ruling R19: launchctl bootout non-zero with "No such process"/"Could not find specified service" = agent wasn't loaded → success, no entry — avoids false failures for idle agents — cost if wrong: a real unload failure with that text is hidden
- Ruling R20: StartupItemScanner adds `scanWithIssues() -> (items, issues: [ScanIssue])`; `scan()` returns `.items`; print-disabled failure and unlistable launch dirs become issues — never assume "enabled" silently — cost if wrong: extra API
- Ruling R21: bootstrap "already loaded" tolerance narrowed to stderr containing "already" (status 5 alone is also a generic I/O error for a bad plist) — supersedes the "status 5 /" part of the Task 12 dispatch — cost if wrong: a real already-loaded case with different text reports failed
- Ruling R22: /Library/LaunchAgents load into each user's gui/<uid> domain, so their disabled state comes from `print-disabled gui/<uid>` (implementer's spike was right; my dispatch wording was wrong); daemons use `print-disabled system`. Reviewer finding #2 overruled; add a system-agent enablement test pinning gui-domain behavior and keep the doc/comment — cost if wrong: system-agent state shown wrong
- Ruling R23: StorageInfo adds availableBytes (volumeAvailableCapacityKey) so the UI can show purgeable = important − available (spec 7.2b) — cost if wrong: one extra field
- Ruling R24: FDA probe .unknown also adds a problem sentence ("Couldn't verify Full Disk Access, so some folders may not be scanned.") — never fail silently — cost if wrong: an extra warning when TCC.db is absent
- Ruling R25: CLI pins ByteCountFormatter locale to en_US_POSIX, declines prompts when stdin is not a TTY unless --yes, and the implementer's manual check runs only read-only commands (doctor/scan/apps/startup list/history/uninstall of a Steam game answered N) — English-only + no destructive action on Kaan's Mac without their say — cost if wrong: less verification coverage of destructive paths
- Ruling R26 (load-bearing, for final fix wave): FullDiskAccessProbe tries, in order, TCC.db (open) then opendir on ~/Library/Safari, ~/Library/Mail, ~/Library/Messages, ~/Library/Containers/com.apple.mail; first existing target decides (EPERM/EACCES → denied, success → granted); none exist → unknown — otherwise FDA can never read as granted on macOS 26 and onboarding (Plan 3) can't verify — cost if wrong: a protected dir that's readable without FDA would read as granted
- Ruling R27 (for final fix wave): when a Steam wrapper's appmanifest is missing, fall back to steamapps/common/<displayName> (R13-validated) as .steamGameData, match .nameBased, mayContainUserData true (review, unchecked) — Kaan's goal is freeing space; a game's data can exist without a manifest — cost if wrong: a same-named folder of another game is offered unchecked
- Ruling R28: final fix wave = the must-fix list above + I6 + Minor 3 + Minor 5, in ONE dispatch (opus). I8 (incremental journaling/SIGINT) and I9 (startup change journaling) deferred as Plan 3 prerequisites; remaining minors and Plan-2 helper items (realpath fail-closed, uid-based env, openat/unlinkat, other homes outside /Users) recorded for Plans 2/3 — cost if wrong: an interrupted CLI clean leaves trashed items without a journal record until Plan 3
- Ruling R29: B1 (TrashMover maps TCC EPERM from access() to needs admin instead of failed "no access (Full Disk Access may be needed)") is real and load-bearing (wrong advice to Kaan; Plan 2 routing) — no second fix wave per process; surface to Kaan in finishing with a recommendation to apply the ~5-line fix before merge — cost if wrong: default clean shows Safari cache etc. as "needs admin"
